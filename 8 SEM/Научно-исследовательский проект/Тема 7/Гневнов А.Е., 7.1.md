# Гневнов А.Е., Задание 7.1

## 1. План работы руководителя

План разбит на этапы, соответствующие полугодовым отчетным периодам (этапам НИР).

### I полугодие: Теоретические исследования
* **Задачи:** Патентные исследования, анализ существующих решений (LLM, RAG-системы), разработка общей концепции и ТЗ.
* **Результат:** Промежуточный отчет о патентных исследованиях и теоретическом обосновании выбора архитектуры.

### II – III полугодия: Практическая разработка
* **II полугодие (Разработка ядра):** Проектирование архитектуры БД, выбор и настройка базовой модели (Qwen/Llama), разработка gRPC-интерфейсов.
    * **Результат:** Промежуточный отчет с описанием программной архитектуры и прототипа «helperbot-core».
* **III полугодие (Интеграция и Frontend):** Разработка пользовательского интерфейса, интеграция базы знаний, дообучение модели.
    * **Результат:** Промежуточный отчет о результатах лабораторных испытаний и готовности бета-версии.

### IV полугодие: Апробация и финализация
* **Задачи:** Опытная эксплуатация (апробация) в реальных условиях, сбор обратной связи через опросы, корректировка алгоритмов, оформление документации по ГОСТ 7.32–2017.
* **Результат:** Итоговый отчет о НИР, акт о внедрении.

---

## 2. Состав рабочей группы

Для эффективной реализации проекта предлагается следующая структура команды:

* **Руководитель проекта (Principal Investigator):** Координация, методологическое обеспечение, контроль сроков и качества отчетов.
* **Backend-разработчик (Go/gRPC):** Ответственный за серверную часть, микросервисную архитектуру и интеграцию с ИИ.
* **ML-инженер / Data Scientist:** Настройка и оптимизация больших языковых моделей, подготовка датасетов для базы знаний.
* **Frontend-разработчик:** Создание пользовательского интерфейса сервиса и веб-портфолио проекта.
* **Технический писатель / Аналитик:** Сбор первичной информации, проведение опросов при апробации, оформление отчетной документации по стандартам.

---

## 3. Организация контроля выполнения работ

Контроль будет осуществляться на нескольких уровнях для обеспечения достоверности и актуальности результатов:

* **Оперативный контроль (еженедельно):** Проведение рабочих совещаний  для оценки статуса задач в рамках текущего этапа.
* **Технический контроль (непрерывно):** Code review, тестирование функционала (экспериментальный метод) и проверка соответствия разработки техническому заданию.
* **Этапный контроль (раз в полгода):** Внутренняя защита промежуточного отчета перед научным советом, проверка оформления по ГОСТ 7.32–2017.
* **Внешний контроль (апробация):** Оценка качества работы сервиса через анкетирование пользователей и мониторинг точности ответов системы.
