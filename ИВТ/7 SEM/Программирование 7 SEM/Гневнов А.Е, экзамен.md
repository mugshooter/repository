*Строки:*
```
import threading
import time

def worker(number):
    print(f"Поток {number}: текущее время {time.ctime()}")

threads = []
```

### 5.5. q4_5 - Теоретически опишите работу OAuth2 Authorization Code Flow: роли (Resource Owner, Client, Authorization Server, Resource Server), ключевые шаги, зачем redirect_uri и state, чем access token отличается от refresh token. Без кода.
*Тип:* comment (обязательный)
*Строки:*
В Authorization Code Flow Resource Owner (пользователь) хочет дать доступ Client (приложению) к своим данным на Resource Server.

Resource Owner (Владелец ресурса): Это пользователь (вы). Человек, у которого есть аккаунт на сервисе (например, в Google) и который хочет разрешить приложению доступ к своим данным.

Client (Клиент): Приложение или сайт, которому нужен доступ к вашим данным (например, сервис Spotify, запрашивающий список ваших контактов в Facebook).

Authorization Server (Сервер авторизации): «Паспортный стол». Сервер, который проверяет личность пользователя и выдает разрешения (коды и токены).

Resource Server (Сервер ресурсов): «Хранилище». Сервер, где лежат реальные данные (ваши фото, контакты или письма). Он отдает их только при предъявлении валидного токена.

1. Client отправляет пользователя на Authorization Server.
2. Пользователь входит в систему и подтверждает доступ.
3. Сервер возвращает временный Code через redirect_uri (безопасный URL возврата).
4. Client со своим секретом меняет Code на токены. state нужен для защиты от подделки запроса. Access token — короткоживущий ключ для данных. Refresh token — долгоживущий ключ для обновления Access token'а.

### 9.2. q8_2 - Выберите только интеграционные паттерны EIP (лишние варианты — не EIP).

### 9.3. q8_3 - Опишите общий интеграционный сценарий (тема 08): как организуются сбор, маршрутизация, преобразование/обогащение сообщений и мониторинг без привязки к конкретному проекту.
*Тип:* comment (обязательный)
*Строки:*
В типичном сценарии компонент Consumer забирает данные из источника (файл, очередь, API). Затем данные проходят через Translator (нормализация формата, например XML в JSON). Далее Router определяет, куда направить сообщение на основе условий. В конце сообщение попадает к Producer (целевая система), а копия данных может отправляться в систему мониторинга (через Wire Tap).

### 9.4. q8_4 - Объясните своими словами, что такое паттерн Wire Tap и для каких целей он используется в интеграционных системах.
*Тип:* comment (обязательный)
*Строки:*
Wire Tap — это паттерн, который позволяет ответвить поток сообщений. Он создает копию сообщения и отправляет её в отдельный канал, не прерывая и не изменяя основной поток обработки. Используется для логирования, аудита или анализа данных "на лету"
