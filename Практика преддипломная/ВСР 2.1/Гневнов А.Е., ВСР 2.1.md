## **1. Сценарий демонстрации**

Демонстрация построена по принципу «снизу вверх»: сначала показывается развёртывание инфраструктуры, затем — пользовательский сценарий взаимодействия, и в финале — внутренние артефакты (логи, БД, gRPC-вызовы) для подтверждения корректности работы сервиса.

### **Шаг 1. Развёртывание комплекса *(1 минута)***

**Действие.** В терминале выполняется команда:

make compose-up

**Что комментировать.** Команда автоматически клонирует или обновляет репозитории, собирает Docker-образы, запускает контейнеры в правильном порядке (сначала PostgreSQL-мастера, затем миграции, затем прикладные сервисы) и создаёт кастомную модель `support-bot` в Ollama.

**Если уже запущено заранее.** Пропустить шаг, выполнить `docker ps` и прокомментировать состав комплекса по выводу.

### **Шаг 2. Авторизация в Telegram-боте *(30 секунд)***

**Действие.** Открыть диалог с ботом в Telegram, отправить команду `/start`.

**Что комментировать.** Бот распознаёт пользователя по Telegram ID, обращается к `helperbot-core` через gRPC, и в зависимости от роли формирует динамическое меню. Для пользователя с ролью администратора в меню присутствует кнопка «Чат с ИИ» — именно она открывает доступ к AI-сервису.

### **Шаг 3. Создание нового диалога с AI *(30 секунд)***

**Действие.** Нажать кнопку «**Чат с ИИ**».

**Что комментировать.** При первом обращении пользователя `helperbot-tg` обнаруживает отсутствие `ChatID` в кэше и вызывает `ChatService.NewChat`, который проксируется через `helperbot-core` в `helperbot-ai`. AI-сервис генерирует новый UUID, сохраняет запись в таблице `chats` и возвращает идентификатор. Пользователю отправляется приветственное сообщение.

**Контрольный вывод в логах** (второй терминал):

helperbot-ai  /chat.ChatService/NewChat  OK  ~5 ms

### **Шаг 4. Базовый сценарий: вопрос — ответ *(1 минута)***

**Действие.** Отправить боту первый демонстрационный вопрос (см. список в разделе 2, вопрос 1).

**Что комментировать.** `helperbot-tg` переводит пользователя в состояние `PendingActionWaitAiAnswer`, вызывает `ChatService.SendMessage`. AI-сервис проверяет лимит запросов SQL-фильтрацией по временно́й метке, загружает историю диалога из PostgreSQL (на первом сообщении она пуста), формирует контекстный запрос к Ollama, получает ответ, сохраняет в БД пару «вопрос — ответ» и возвращает результат по цепочке.

**Ожидаемое время инференса:** 3–15 секунд в зависимости от ресурсов хоста.

### **Шаг 5. Демонстрация контекстной осведомлённости *(1 минута)***

**Действие.** Отправить уточняющий вопрос (раздел 2, вопрос 2), не повторяя контекст из первого.

**Что комментировать.** При формировании запроса к Ollama AI-сервис загружает **всю** историю диалога из таблицы `messages` в хронологическом порядке и передаёт её модели. Поэтому ответ учитывает предыдущий обмен, а не отвечает «как с нуля». Это ключевое отличие от stateless-чатботов.

### **Шаг 6. Демонстрация контекстной осведомлённости *(1 минута)***

**Действие.** Отправить уточняющий вопрос (раздел 6, вопрос 2), не повторяя контекст из первого.

**Что комментировать.** При формировании запроса к Ollama AI-сервис загружает **всю** историю диалога из таблицы `messages` в хронологическом порядке и передаёт её модели. Поэтому ответ учитывает предыдущий обмен, а не отвечает «как с нуля». Это ключевое отличие от stateless-чатботов.

**Если демонстрация устная** — попросить присутствующих оценить, насколько ответ согласуется с предыдущим контекстом.

### **Шаг 7. Демонстрация эскалации к оператору *(1 минута)***

**Действие.** Отправить заведомо узкоспециализированный вопрос (раздел 6, вопрос 3).

**Что комментировать.** Системный промпт модели `support-bot` содержит инструкцию: при незнании ответа предлагать обратиться к живому оператору. Модель должна сформировать вежливый отказ с рекомендацией эскалации. Это реализация одного из функциональных требований без дополнительного программного кода — исключительно через конфигурацию языковой модели.



## **2. Перечень демонстрационных материалов**

### **Вопросы для базового сценария (шаги 5–6)**

1. **Первое сообщение:** «Здравствуйте! Подскажите, как зарегистрировать нового читателя в системе?»
2. **Уточняющее сообщение (с опорой на контекст):** «А какие документы для этого нужны?»

### **Вопрос для демонстрации эскалации (шаг 7)**

1. «Какой инвентарный номер у сервера, на котором развёрнута АБИС нашего филиала?» — модель не располагает специфической информацией и должна предложить обратиться к оператору.
